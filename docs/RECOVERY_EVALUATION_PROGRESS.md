# 추천 방법 개선 검증 — 진행 결과

2026-11-23 실제 실행. 이번 작업은 실험 구현과 별도 기간 평가까지 완료했다. **추천 정확도가 전반적으로 개선됐다는 결론은 얻지 못했다.** 운영 후보와 기존 화면의12월0/10 결과는 바꾸지 않았다. 새 결과는 아래 연구 산출물에서 확인한다.

## 원래0/10은 왜 나왔나

2025년12월 인기 대여소10곳 가림 실험이다.

| 도시 |300m 내 생성 후보 없음 |후보 있으나 상위10 복구 실패 |복구 |
|---|---:|---:|---:|
|서울|10|0|0|
|대전|9|1|0|
|세종|10|0|0|

이는 점수 조정만으로 해결할 수 없는 후보 생성 제약이 크다는 뜻이다. 후보가 없어진 정확한 개별 공간 원인을 한 가지로 단정하지 않는다. 새 JSON에는 후보까지의 최소 거리·남은 대여소 거리·최초 근접 순위를 기록했다.

## 별도7월 평가 결과

아래는 **교통 공백 조건에 맞는 관측 대여소 중 이용량 상위10곳**을 숨긴 실험이다. 원래12월 인기10곳과 대상·시기가 다르므로0→3으로 개선됐다고 비교하면 안 된다. 새로 설치할 곳의 수요 예측 실험도 아니다.

| 도시 |기존 방법 복구@10 |6월에서 선택해 고정한 방법 복구@10 |후보 생성 가능 목표500m→250m |
|---|---:|---:|---:|
|서울|3/10|2/10|8/10→10/10|
|대전|0/10|1/10|3/10→7/10|
|세종|1/10|1/10|3/10→10/10|

서울·대전은 개발용6월에서500m 격자의 주변 이용량 순위가 선택됐다. 세종은500m 균등점수가 선택됐다.250m는 후보 생성 가능성을 늘리지만 TOP10 복구를 일관되게 개선하지 않았다.

무작위 표본10곳 평가에서는 서울0/10, 대전0/10, 세종1/10이었다.1km 구역 전체를 숨긴 평가에서는 서울0/18, 대전2/24, 세종1/43이었다. 대전의 구역 평가는 기존0/24보다 높지만 한 구역의 결과라 전 도시 일반화로 해석하지 않는다. 목표가10개보다 많으면복구@10 상한은10/N이다.

7월 대전 구역 평가에서는14개 목표가 상위 후보의300m 안에 있었지만, 실제 일대일 대응은2개뿐이었다. 같은 후보 주변에 목표가 몰리기 때문이다. 개별 근접 여부를 복구 건수로 과장하지 않도록 audit.json에 충돌을 별도 표시했다.

## 실제 데이터와 누출 방지

|도시|2025년6월 이동건수 / 관측일|2025년7월 이동건수 / 관측일|
|---|---:|---:|
|서울|4,004,290 /30|3,517,166 /31|
|대전|601,386 /30|540,208 /31|
|세종|267,095 /30|255,767 /31|

- 기존data/individual/{city}/analysis.sqlite의 개별 이력 집계를mode=ro로 읽었다. 기간별 날짜·합계 및 미연결 endpoint 건수도 결과에 기록했다.
- 가린 대여소가 출발/도착인OD를 모두 제거한 뒤 남은 이용량을 재집계했다. 원래 이용량은 평가 정답에만 쓰고 입력으로 되돌려 넣지 않았다.
- 6월점수만으로 도시별 방법을 선택하고 selection-lock.json을 저장한 뒤7월OD를 읽었다.7월 실패를 보고 방법을 재선택하지 않았다.
- 전체18개 가림 실행×2격자×4순위=144조건, Recall@10·@20 총288개 매칭 지표를 별도 감사했다. 무작위 비교는 후보풀별30회다.
- 입력SQLite는 시작 시SHA256 기록, 종료 시크기·mtime 동일성 확인. 코드·소규모 참조자료는 추가SHA256 재검증했다. 기존 DB·KPI·후보 점수는 변경하지 않았다.

## 남은 한계와 다음 작업

1. **후보 생성과 순위는 분리해 개선해야 한다.** 촘촘한 격자로 기회를 늘린 뒤, 같은 지역에 TOP10이 몰리지 않도록 중복 면적·공간 분산을 고려하는 순위 방식을 다음 개발 후보로 삼는다. 이번7월에 유리하게 맞추지 않고8월 등 미사용 평가기간을 새로 지정해야 한다.
2. **목적별 성공 기준이 다르다.** 수요 재발견은 실제 위치·이용량으로 평가하고, 공백 보완은 중복 제거 추가면적·기존 이용 접근성·설치 제약으로 평가한다. 공백 해소가 인기 대여소 재현과 같지는 않다. 코드의 신규 후보는 앵커거리로 모두 제외하는 방식이 아니라 공백 비율을 점수에 반영하는 방식이며, 이번 대상 코호트에만 앵커500m 밖 조건을 적용했다.
3. 위치·앵커·시설·인구는 고정된 최신 참조다. 과거6/7월의 동일성은 미확인으로, 완전한 과거시점 예측 검증이 아니다. 두 여름달만으로 겨울·계절 전체 강건성을 입증하지 않는다.
4. 실제 보행망·장애물·설치 가능 토지 확인이 필요하다. 도로망 검증은 이번에 수행하지 않았다.
5. 세종 동일월 BRT승하차량은 미확보다. 기존N/A를 억지로 채우지 않았다. 실제 환승·재고 부족·설치 효과도 추정하지 않았다.

## 후속 구현 페이지 반영

같은 날짜 후속 요청으로 web·React의 개선 지역 찾기 검증 영역에 진행 카드·도시별 비교표를 연결했다. 위의 ‘새 결과는 연구 산출물에서 확인’은 최초 실험 완료 시점 기록이며, 현재는 화면에서도 별도 연구 실험으로 확인할 수 있다. 서비스 공통12월과 기존0/10은 유지하며6/7월결과를운영점수로반영하지않는다. 기본조회API의 recovery_evaluation 추가필드로축약저장값만읽고,자료/결과지문이달라지면추가실험만미확보표시한다.
