**후보 검토·시간 가정·공통 기준·시간 홀드아웃·알고리즘 판단 사례·현재 전체기간 Spark 집계·Solar 자율 도구 선택을 추가 검증했다. 전체 여정과 실제 설치 효과까지 해결됐다는 의미는 아니다.** 기존 원본·공통 DB·사전 집계·운영 점수와 순위는 유지했다. 기존 화면 디자인에 분석 결론의 설명과 접힌 추가 검토 표만 보완했다.

## 1. 전체 여정 비교: 미완료

로컬 자료의 기존 감사 기록과 raw 파일 목록을 확인한 뒤 공식 출처를 조사했다.

- [대전 공식 열차시각표](https://www.data.go.kr/data/15000960/fileData.do?recommendDataYn=Y)는 활용 신청·인증키 관련 안내가 있다. 분석에 필요한 2025년 동시점의 전체 여정용 노선·시각표 조합은 확보하지 못했다.
- [세종 공식 BRT 시간표 PDF](https://mbis.sejong.go.kr/mobile/main/fileDownload.do?file_name=1001+BRT_TIMELIST.pdf)는 실제 다운로드했다. 48,919바이트, SHA-256 `4751fd72ce9916dc550ff903ed2816633d4a9280f82b14886aa7b1db238da9d2`. 텍스트에 ‘7/20~24 시범운행’이 있고 적용 연도를 검증하지 못해 분석에서 제외했다.
- 같은 출발·도착 지점, 출발시각, 운행일, 승차·하차·대기·환승을 모두 연결한 비교는 아직 없다. 기존 도보→거점과 자전거→반납소→거점 비교를 전체 여정으로 이름만 바꾸지 않았다.
- 결과 JSON의 `full_journey.available=false`를 유지한다. 현재 자료만으로 버스·철도 전체 이동 시간이나 실제 환승률을 생성하지 않는다.

## 2. 후보와 경로 대안: 부분 확대

각 도시 전체기간의 원래 상위5곳을 대상으로 최근접 경로를 점검했다. 상위3곳은 가까운 앵커2개와 앵커300m 내 반납 대여소2개까지 부분 탐색했다. 기존 캐시를 우선 사용하고 신규 조회는 전체30회로 제한했다. 예산은 서울20회·대전10회에서 소진되어 세종의 미캐시 대안은 추가 확인하지 못했다. 이는 도시별 동일한 경로 탐색 완전성을 확보한 실험이 아니다.

| 도시 | 점검 대상 | 2분 가정에서 도보보다 빠른 연결을 확인한 후보 | 미확인·느림 |
|---|---:|---:|---|
| 서울 | 5곳 | 5곳 | 없음 |
| 대전 | 5곳 | 2곳 | 원래1·5순위 미확인,2순위 느림 |
| 세종 | 5곳 | 1곳 | 원래1·3·4·5순위 미확인 |

‘미확인’에는 경로 접속 불확실, 반납 대여소 부재, 신규 조회 예산 소진이 포함된다. 미확인을 불가능 또는 효과0으로 바꾸지 않았다.

별도 경로 검토 순서는 **확인된 대안 중 2분 가정에서 도보보다 빠른 후보의 연계 모델 시간 오름차순**이다. 원래 운영 점수순과 목적이 다르고 전역 최적 경로·최종 설치 추천 순위가 아니다.

- 서울: 기존4→1→2→3→5순위.
- 대전: 기존4→3순위. 기존1순위를 경로 검증 없이 먼저 추천하지 않도록 구분한다.
- 세종: 기존2순위만 조건부 검토.
- 대여·반납0/2/5분의 가정별 단축 시간을 보존했다. 예컨대 대전 기존2순위는2분 가정에서3.895분,5분 가정에서6.895분 더 느리다.
- 대전 일부 도보 경로의 큰 우회로 큰 단축값이 나온다. 실제70분 절약 등의 실측 주장으로 사용하지 않으며 접속·우회·현장 통행을 추가 확인해야 한다.

웹·React ‘분석 결론’의 개별 도시에서 **상위 5곳 추가 경로 검토**를 펼치면 원래 순위·경로 판단·별도 검토순서·도보/연계 모델 시간을 확인할 수 있다. 원래3후보의 기본 경로 수치와 추가 대안 경로는 별도로 표시한다.

## 3. 동일 특징과 시간 홀드아웃

동일한 공통 완전 관측 월 중 2025년1·4·5·6월을 훈련 구간,7~12월을 평가 구간으로 고정했다. 세 도시 모두 인구를 제외한 시설 수·주변1km 관측 대여·접근 공백 비율의 동일3개 특징으로 후보를 다시 비교했다.

훈련 자료에서만 PageRank를 계산하고 공통기준90%+PageRank 주변 합의 백분위10%라는 탐색적 보조 실험을 수행했다. 이 가중치를 평가 결과로 조정하거나 운영 순위에 적용하지 않았다.

| 도시 | 공통기준 상위3곳 중 평가기간 상위10위 | PageRank 보조 후 상위3곳 일치 | 평가기간 주변 관측 대여 중복제거 합: 공통기준→보조 |
|---|---:|---:|---:|
| 서울 | 3/3 | 2/3 | 274,649→526,692건 |
| 대전 | 3/3 | 3/3 | 243,448→243,448건 |
| 세종 | 3/3 | 3/3 | 95,062→95,062건 |

평가기간 수요는 후보1km 내 기존 대여소별 한 번만 합산했다. 후보끼리 겹친 대여소의 이용량을 중복 합산하지 않는다.

**해석 범위:** 시간적으로 분리한 같은 도시의 관측 수요 대리변수·순위 반복성 점검이다. 평가기간 점수의 상위10위를 정답 설치 장소로 간주하지 않는다. 후보의 공간 참조·현재 대여소 마스터는 고정되어 있어 과거 시점의 부지·시설을 완전히 재현하지 못한다. 다른 도시로 학습 모델을 전이한 검증이나 실제 신규 수요·설치 효과 예측이 아니다. PageRank는 수요와 상관될 수 있으며10%가 최선이라는 증거도 없다.

## 4. 군집·시간 패턴의 판단 사례

훈련4개월의 시간대별 대여 비중으로만 K-means3개 군집을 재계산했다. 훈련 대여100건 이상 대여소의 수요순 인접 쌍 중, 대여량 차이10% 이내이면서 코사인 유사도가 가장 낮은 쌍을 사례로 선택했다.

| 도시 | 대여소 | 훈련 대여 | 집중 시각 | 훈련 Silhouette |
|---|---|---:|---|---:|
| 서울 | ST-2029 / ST-1712 | 7,242 / 7,243건 | 08 / 17시 | 0.210 |
| 대전 | ST0272 / ST0167 | 100 / 100건 | 07 / 23시 | 0.132 |
| 세종 | SJ_00458 / SJ_00114 | 188 / 192건 | 18 / 15시 | 0.248 |

이용량만으로 같은 운영 시간대를 적용하기 어렵다는 사례다. 실제 재고·일별 반복성 검증 없이 출근형·주거형 등의 역할을 확정하거나 부족 수량을 제시하지 않는다. 군집의 낮은 분리도를 숨기지 않고 순위에 군집번호를 가중치로 넣지 않았다. 대전·세종 사례의 적은 표본은 추가 확인이 필요하다.

## 5. 현재 전체기간 Spark 재현

현재 세 도시 전체기간의 daily OD 전체를 읽어 Spark local[2]로 월별 SUM(trip_count)를 실행했다. 임시 CSV는 각 도시 검증 후 정리했으며 원본과 DB는 읽기 전용으로 열었다.

| 도시 | daily OD 행 | 월수 | 실제 이동 합계 | Spark 집계 시간 | SQLite 월별 해시 |
|---|---:|---:|---:|---:|---|
| 서울 | 20,994,451 | 12 | 37,176,546건 | 17.78초 | 일치 |
| 대전 | 10,773,929 | 27 | 14,992,420건 | 6.12초 | 일치 |
| 세종 | 10,082,096 | 72 | 12,903,589건 | 5.60초 | 일치 |

41,850,476개 daily OD 행,65,072,555건 이동의 월별 결과를 일치 검증했다. 시간은 CSV 읽기부터 결과 materialize까지이며 SQLite 추출·CSV 작성·Spark 시작 시간을 포함하지 않는다.

**현재 전체기간 집계 단계의 재현이다. 원본 정규화 전체를 Spark로 다시 처리하거나 분산 클러스터의 확장성을 증명한 결과는 아니다.** 기존 pandas/SQLite 정규화와 기존36회 엔진 비교 기록을 보존했다.

## 6. Solar 자율 선택 평가와 수정

도구 이름을 알려주지 않고 각 도시의 전체기간 결론·연결 경로·시간상 이점·한계를 질문했다.

- 최초3질문: 모두 실제 도구를 선택했지만 서울은 공통기간 결론을 선택했고 대전·세종은 결론 도구를 선택하지 않았다. 실패를 보존했다.
- 도구 설명과 시스템 안내를 보완하고, 전체기간 결론 요청에는 서버가 동일 범위의 결론 도구를 확인하는 보조 가드를 추가했다. 모델의 자율 선택과 서버 보조 가드를 evidence.initiator로 구분한다.
- 두 번째3질문에서는 모델이3/3 동일 전체기간 결론 도구를 선택했다. 대전은 보류 요약에서 후보ID가 빠져 실패로 기록했다.
- 구조화 결론을 보류 요약에 포함하고 음수 단축값을 보존하도록 수정했다. 대전1질문을 추가 실호출해 후보ID·기간을 확인했다. 세종은 이미 결론 도구가 있는 경우 불필요한 전체 자료 현황 가드를 생략하도록 보완했다. 이 마지막 중복 조회 생략은 회귀검증했고 추가 유료 호출은 하지 않았다.
- 최종 각 도시1개씩의 기록은 HTTP200·자율 도구 선택·결론 도구 선택·전체기간·후보ID·기간 인용6개 검사 모두3/3이다.
- 최종 표시 본문은 서울1건이 Solar 해석,대전·세종2건이 서버의 검증된 도구 요약이다. **자유 서술이 전부 검증을 통과했다는 뜻이 아니다.**
- 유료 사용자 질문 실행7회,기록된 공급자 호출14회,토큰645,591개. 실패·수정 전후 원문은 initial-solar와 pre-finalizer에 보존했다. 남은 테스트는 저장 응답 재생을 사용했다. 한 질문의 큰 도구 응답 비용도 확인되어 향후 입력 축약 검증이 필요하다.

## 7. 남은 부족한 부분과 우선순위

1. **동일 OD 전체 여정 비교:** 2025년 적용이 확인된 정류장 순서·운행일·시간표와 대기/환승을 확보해야 한다. 현재 가장 중요한 목표상 공백이다.
2. **도로망 검증의 완전성:** 세종 대안과 미확인 후보를 보완하고 큰 우회 경로를 현장과 대조해야 한다. 현재 부분 탐색의 별도 검토순서를 최종 설치 순위로 사용하지 않는다.
3. **현실의 개선 효과:** 부지·허가·거치 용량·재고·실제 환승 정의, 설치 전후 및 비교 지역 자료가 없다. 효과 크기·재배치 대수를 확정할 수 없다.
4. **시간 검증의 참조 편향:** 과거 개폐소·시설·인구·위치를 복원하고 학습 기준을 잠근 추가 외부 기간으로 검증해야 한다. 이번 평가 점수를 정답 입지로 해석하면 안 된다.
5. **군집·그래프 보조 기준의 일반화:** PageRank10%는 탐색이다. 군집 분리도는 낮고 일부 사례 표본은 적다. 시간 블록·반복 분할·독립 지표로 재검증하기 전 운영 점수 변경을 보류한다.
6. **Spark 원본 경로:** 현 전체기간의 원본 정제·중복 제거·대여/반납 전체 파이프라인을 Spark로 재현한 것은 아니다. 입력 정제 규칙을 동일하게 구현하고 엔진별 결과·자원 사용을 검증해야 한다.
7. **Solar 품질과 비용:** 세 도시 소수 질문만으로 일반화할 수 없다. 전체 자유 서술, 숫자의 의미·단위·후보 대상 일치와 큰 도구 응답의 토큰 예산을 확대 검증해야 한다.

## 8. 재현·검증 기록

```bash
python -m scripts.validate.final_validation
python -m scripts.validate.final_training_patterns
python -m scripts.validate.final_spark_scope
python -m scripts.validate.final_solar_agent --live
python -m pytest backend/tests -q

```

경로 검증은 저장 체크포인트를 재사용하며 신규 조회 예산은 실행당30회다. Solar는 도시별 저장 응답이 있으면 재호출하지 않는다. 이전 응답과 결과를 임의 삭제하지 말고 조건 변경 시 새 출력 폴더를 사용한다. 신규 배치 코드와 참조가 변경되면 기존 체크포인트를 그대로 새 실험으로 취급하지 않는다.

- 자동 테스트212개 통과(기존 경고40건).
- React TypeScript·프로덕션 빌드 및 web 빌드 통과.
- 공개 웹·React에서3도시·전체 선택의 기존 범위를 확인. 추가 경로 표는 PC1440px·모바일390px에서5행 표시·가로 문서 넘침 없음·페이지 오류 없음.
- 공통 원본5파일 SHA-256 불변 확인(analysis.sqlite,kpi_cache.sqlite,stations.csv,station_usage.csv,kpi_inputs.json).
- 기존 원본·사전 집계 DB 삭제·초기화 없음. 서버 재시작·별도 배포 명령·커밋·푸시 없음. web 현재 프로젝트의 빌드와 동적 API가 공개 URL에서 읽히는 상태를 확인했다.
