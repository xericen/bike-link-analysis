# 공통 여러 달 비교·최종 후보 연결 경로·분석 결론

2026-11-23. AI 분석 보고서 아래에 **분석 결론** 메뉴를 추가했다. 결론은 저장된 관측값·월별 재계산·도로망 점검으로 구성하며 LLM이 임의로 생성하지 않는다. 기존 전체12월·개별전체기간·추천 점수·원본·DB는 보존한다.

## 1. 같은 기간 비교

세 도시 모두 관측 날짜가 완전한 **2025년1월·4~12월, 10개월/306일**만 비교한다. 대전의 날짜가 불완전한2·3월은 제외하고 0으로 보충하지 않는다. 이 목록은 불연속이므로2025년전체/연간 결과라고 표현하지 않는다. 날짜 완전성이 개별 이력·좌표 완전성을 보증하는 것은 아니다.

| 도시 | 공통10개월 대여 | 하루 평균 | 앵커 근접 OD 비중 | 위치 미연결 이동 비중 |
|---|---:|---:|---:|---:|
| 서울 | 32,693,864 | 106,842.7 | 61.552% | 2.600% |
| 대전 | 5,107,326 | 16,690.6 | 27.129% | 0.539% |
| 세종 | 2,333,498 | 7,625.8 | 73.868% | 0.933% |

서울·대전은 지하철, 세종은 BRT 기준이다. 비중은 실제 환승률이 아니며 도시 규모와 교통수단의 차이를 운영 성과 순위로 해석하지 않는다. 새 화면에서 월별 인접 이용 비중·하루 평균·위치 미연결 비중을 전환할 수 있다.

## 2. 후보를 한 번만 고르지 않고 월별로 다시 계산

기존500m격자·300m기존대여소간격·시설/확인된 인구/주변1km수요/공백의 균등 점수 규칙을 유지했다. 서울12·대전27·세종72개월의 실제 SQLite 대여소별 월 합계를 읽어 기존 월간 집계 총량과 모두 대조했다. 고정 공간 참조에서 월별 주변 수요를 재집계하고 각 월 전체 적격 후보를 다시 순위화했다.

- 전체 선택의 최종 후보: 공통10개월 수요를 합쳐 같은 점수로 고른 도시별3곳.
- 개별 선택의 최종 후보: 기존 전체기간 계획의 신규 상위3곳과 ID가 같음을 검증했다. 관측기간은 서울2025년, 대전2024-08~2026-10, 세종2020~2025이다.
- 재등장 분모: 날짜 완전성이 확인된 달만 사용(서울12, 대전25, 세종71). 신규 입지의 월별 순위를 계산했으며 기존 취약 대여소의 월간 TOP10을 신규 후보의 반복성으로 잘못 쓰지 않았다.
- 같은 관측자료에서 선정한 후보의 사후 반복성 점검이다. 독립 미래 예측 검증이나 설치 후 효과 검증이 아니다.

## 3. 연결 경로 점검

후보→반납 대여소→역/BRT의 사슬을 점검했다. 후보의 최근접 직선거리 앵커와 그 앵커300m 내에서 해당 기간 이용·좌표가 확인된 최근접 대여소를 선택했다. 전 앵커·모든 반납소 조합의 최단 경로 탐색은 아니다.

- 직접 도보: 후보→앵커의 OSM foot 경로.
- 연계 시나리오: 후보→반납 대여소의 OSM cycling + 대여소→앵커의 foot + **대여/반납2분 가정**.
- 두 연계 구간의 양 끝 스냅이 모두50m 이내인 경우만 모델 연결로 집계했다. 경로 없음/큰 접속오차/서비스 실패는 직선거리로 대체하지 않았다.
- 앵커300m 내 이용 대여소가 없으면 반납소 미확인으로 보류한다. 다른 반경·다른 앵커의 가능성까지 부정하는 것은 아니다.
- 경로가 있어도 도보보다 모델 시간이 길면 우선도 재검토로 표시한다.10/15/20분 기준별 후보 수는 모델 연결 후보에 대해서만 계산한다. 인구 커버리지나 도시 전체 접근률이 아니다.
- 현재 OSM 그래프와 캐시 조회일을 공개한다. 과거 관측 당시 경로·현장 통행·실측 시간·설치 가능성·재고/거치 용량은 미검증이다.

| 범위 | 도시 | 모델 연결/3 | 도보보다 모델 시간이 짧은 후보/3 |
|---|---|---:|---:|
| 공통10개월 | 서울 | 3/3 | 3/3 |
| 공통10개월 | 대전 | 2/3 | 1/3 |
| 공통10개월 | 세종 | 1/3 | 1/3 |
| 개별전체 | 서울 | 3/3 | 3/3 |
| 개별전체 | 대전 | 2/3 | 1/3 |
| 개별전체 | 세종 | 1/3 | 1/3 |

각 범위에서 모델 연결은9개 중6개이다. 연결 여부와 시간 단축을 구분하며, 시간 단축 모델 후보는 총5개이다. 같은 위치가 두 범위에 등장할 수 있으므로 두 범위의 후보 수를 합산하지 않는다.

공개 FOSSGIS OSRM 서버를 유효 User-Agent로 최대1초당1요청 이하(1.1초 간격) 사용했다. 최초 실행은 새19요청과 기존 캐시를 사용했고 최종 실행은 캐시만 사용해 추가 요청0회였다. 외부 서비스가 연속3회 실패하면 요청을 중단하고 미확인으로 남기는 회로차단을 구현했다. [제공기관·이용정책](https://routing.openstreetmap.de/about.html), © OpenStreetMap contributors; FOSSGIS OSRM.

## 5. 화면·API·AI

- 웹/React의 AI 분석 보고서 바로 아래에 분석 결론 메뉴를 추가했다.
- 전체는 공통10개월 결론, 개별은 해당 도시 보유전체기간 후보를 표시한다. 공통 비교표는 별도10개월임을 명시한다.
- 기존 메뉴로 돌아가면 전체12월/개별전체기간 동작을 유지한다. 새 결론에 구12월 정보가 혼재하지 않도록 별도 기간 제목/출처를 사용한다.
- FastAPI GET /api/conclusion?city=all 또는 city=seoul/daejeon/sejong. scope=common/individual을 지원하되 all+individual은422.
- Solar get_project_conclusion은 선택 전체기간과 정확히 맞는 경우만 기본 반환한다. 기존12월과 공통10개월을 자동 대체하지 않는다. scope=common을 명시한 경우에만 별도 참고범위·선택 맥락 기간을 함께 반환한다.
- 웹 요청에서 SQL재집계·경로 API·LLM을 실행하지 않는다. 이번 작업에서 새 유료 AI 호출은 하지 않았다.

## 6. 검증

- 전체 백엔드206개 통과. 공통 월 목록/306일/기존 월 합계, 신규 후보의 원래ID·월별순위·완전월 분모, 스냅50m/반납소300m/시간 합산, 미확인 보류, 읽기 전용 API, scope 분리, 캐시·회로차단·출력 복사, 느린 연결의 우선도 재검토를 검증했다.
- React TypeScript/프로덕션·web 빌드 통과. 공개 WIZ4가지 도시 선택·모바일·원래 메뉴 복귀, React3도시/공통 전환을 확인했다. 최종 브라우저 기록은 [browser.json](browser.json)에 보존한다.
- 원래 공통 분석 파일5개 SHA-256·수정시각·크기 동일, 공통16조합128집계·개별52개씩 준비 상태 검증 통과.
- 기존 점수·원본·DB 초기화/삭제 없음. 기존 미커밋 변경 보존. 커밋/푸시·별도 배포 명령·서비스 재시작 없음.

## 재현

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=2 python -m scripts.validate.build_conclusion
python -m pytest backend/tests -q
python scripts/deploy/release.py --verify-only
```

배치는 검증된 기존 원본/개별DB/월간참조/위치·시설·경계 자료를 사용한다. 체크포인트는 코드·참조내용·기존 분석 버전·DB크기/시각이 같은 경우만 재사용한다. 입력/코드가 달라지면 기존 실험을 보관하고 새 버전으로 계산한다. 초기 체크포인트는 initial-pass 폴더에 보존하며 현재 결과는 results.json이다.

## 남은 한계

반복성·현 도로망 모델의 연결까지 근거를 강화했으나 실제 환승, 현장 통행, 과거 공간 참조 동일성, 설치 후 이용 변화는 미검증이다. 최근접 앵커/반납소 외의 대안 경로, 300m 반납소 기준 민감도, 부지 허가와 과거 재고 자료가 다음 검토 대상이다. 재배치는 여전히 검토 후보이며 실제 이동 대수를 산출하지 않는다.
