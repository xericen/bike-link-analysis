# 원래 프로젝트 목표에 따른 분석 결론

공유자전거가 대중교통 접근 공백을 보완할 수 있는 후보와 조건을 분석하고, 도시별로 검토할 수 있는 도구 실행형 웹 시스템을 구현했습니다. 실제 환승 증가와 설치 후 개선 효과는 추가 검증이 필요합니다.

## 1. 교통 취약 후보와 보완 조건

**원래 목표:** 도시별 대중교통의 연결이 취약한 구간을 찾아내고, 공공자전거가 이러한 이동 불편을 보완할 수 있는 조건을 분석한다.

**현재 결론:** 역·BRT에서 먼 이용 대여소와 접근 공백 격자를 찾아 후보지역을 도출했습니다. 반복되는 관측 수요, 거점 인근 반납소까지의 연결, 도보 대비 연계 모델 시간이 유리한지를 함께 검토합니다.

**확인 근거:** 취약 대여소·신규 입지 지도, 월별 후보 반복성, 도로망 연결 사슬 점검.

**상태:** 후보 도출·조건부 검증

**남은 검증:** 공간상 후보지역 분석입니다. 배차 빈도·환승 대기·운행 중단을 포함한 연속 교통 취약 구간과 실제 이동 불편 전체를 검증한 것은 아닙니다.

## 2. 서울·대전·세종 데이터 확보

**원래 목표:** 서울 따릉이와 추가 도시의 공공자전거 대여·반납 이력, 대여소 위치, 대중교통 정류장·노선 및 지역별 접근성 데이터를 확보하여 분석한다.

**현재 결론:** 세 도시의 대여·반납 이력, 위치 마스터, 지하철·BRT·버스 정류장과 공간 참조 자료를 연결했습니다. 결론의 도시 비교는 날짜 관측이 완전한 공통 10개월을 사용합니다.

**확인 근거:** 공통 2025년 1월·4~12월 비교와 서울12·대전27·세종72개월 개별 관측 자료.

**상태:** 핵심 자료 확보·일부 미확보

**남은 검증:** 전체 노선 선형·시각표·배차 자료, 세종 BRT 승하차, 과거 위치 변경·고해상도 인구는 충분하지 않습니다. 확보하지 않은 자료를 확보한 것으로 표시하지 않습니다.

## 3. Spark·군집·이동 흐름과 우선순위

**원래 목표:** Spark로 대규모 이용 데이터를 처리하고, K-means 군집화와 이동 흐름 그래프 분석으로 지역별 특성을 파악한 뒤 교통 취약 후보 구간의 우선순위를 산정한다.

**현재 결론:** Spark 실제 처리와 결과 일치를 검증하고 K-means·PageRank·이동 흐름 분석을 구현했습니다. 후보 우선순위와 동일 설치 수의 점수순·탐욕법·MCLP 비교도 제공합니다.

**확인 근거:** Spark 원본 처리·정합성 기록, pandas/Spark36회 실측, 군집·중심성·이동 네트워크 및 MCLP36개 실험.

**상태:** 분석 구현·판단 연결 보완

**남은 검증:** 현 우선순위는 주로 거리·수요·시설·공백에 기반합니다. 군집·그래프는 보조 해석이며 최종 점수의 직접 항으로 통합되지 않았습니다. 낮은 군집 분리도와 해당 집계에서 Spark가 더 느린 결과를 보존했습니다.

## 4. 접근성 시나리오와 다른 도시 적용

**원래 목표:** 대중교통 단독 이동과 공공자전거 연계 시나리오의 예상 접근성을 비교하고, 데이터가 확보된 다른 도시에서도 선정 기준이 적용되는지 검증한다.

**현재 결론:** 같은 신규 후보 선정 규칙을 세 도시에 적용하고, 후보→반납 대여소→역·BRT의 도로망 모델을 점검했습니다. 직접 도보 접근과 자전거 연계 접근의 모델 시간을 비교하며 느린 연계는 우선도 재검토로 표시합니다.

**확인 근거:** 현재 선택 범위의 모델 경로 연결: 서울 3/3곳 · 대전 2/3곳 · 세종 1/3곳. 대여·반납2분 가정과 10/15/20분 기준의 민감도 제공.

**상태:** 접근 구간 비교·부분 검증

**남은 검증:** 현재 비교는 대중교통 거점까지의 접근 구간입니다. 버스·철도 전체 여정의 단독 통행시간 비교나 실제 환승·설치 후 효과 검증은 아닙니다. 노선·배차·대기시간과 독립 검증 자료가 추가로 필요합니다.

## 5. Solar 도구 실행형 AI와 웹 대시보드

**원래 목표:** 최종적으로 Upstage Solar 기반 도구 실행형 AI 에이전트가 분석 및 비교 도구를 호출해 근거를 설명하는 도시별 취약 구간 지도, 개선 후보 순위와 웹 대시보드를 구현한다.

**현재 결론:** 도시별 취약 후보 지도·개선 순위·비교 대시보드와 Solar 도구 실행 구조를 구현했습니다. AI는 서버 분석값을 조회해 설명하고, 분석 결론 메뉴는 저장된 검증 결과를 직접 보여줍니다.

**확인 근거:** 실제 분석·비교 API, Solar 도구 호출 및 근거 대조, 웹·React 화면과 도시별 결론.

**상태:** 도구·화면 구현

**남은 검증:** 자유 서술 전체의 사실성은 자동 검증되지 않습니다. 새 평가의 렌더러 검증과 자율 도구 선택 검증을 구분하며, 근거가 없는 주장은 보류해야 합니다.

## 종합 판단

연구 목표 중 데이터 기반 후보 탐색·지역 특성 분석·조건부 접근성 비교·도구 실행형 웹 구현까지 수행했습니다. 확충 우선 검토는 반복 수요와 연결 경로를 함께 보고 판단하며, 전체 대중교통 여정과 실제 개선 효과는 후속 검증 대상으로 남깁니다.

분석 결론 메뉴의 목표별 항목과 API·Solar 도구가 같은 정의를 사용한다. 이 정리는 기존 분석을 원래 목표에 맞춰 해석한 것이며 데이터·점수·경로·집계값을 변경하지 않았다.
