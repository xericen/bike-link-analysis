# 입지·지도·순위·운영 개선

## 구현 범위
WIZ 취약 구간 탭과 React 이동 패턴 화면에 신규 입지, 선택 시나리오, 순위 민감도, 재배치 검토를 연결했다. 모든 공간 연산은 배치이며 조회 중에는 준비된 결과와 선택 조합만 읽는다.

## 실제 자료와 시점
- 주민등록 인구: 행정안전부2026-10-31, [15097972](https://www.data.go.kr/data/15097972/fileData.do). 행정동을 구·시로 합산하고 행정 경계 면적으로 나눈 밀도. 실측 격자인구나 유동인구를 생성하지 않는다.
- 도서관·공공개방시설: [15013109](https://www.data.go.kr/data/15013109/standard.do), [15013117](https://www.data.go.kr/data/15013117/standard.do). 공개 다운로드 JS에 명시된 JSON 다운로드 절차로 전량 수집 후 도시·유효 좌표 필터. 시설 레코드 수는 전수 생활시설 수가 아니며 한 건물의 여러 개방 공간이 포함될 수 있다.
- 경계: SGIS2020 기반 [statgarten/maps](https://github.com/statgarten/maps), MIT. EPSG:5179 원본으로 계산하며 도형만 WGS84로 변환한다. 최신 경계와의 차이를 무시하지 않는다.
- 세종: [공식 대여소 마스터15091421](https://www.data.go.kr/data/15091421/fileData.do),2026-05-26 위치. 기존 이력ID728개 중726개를 정확한 ID 및 등록일<=2025-10-31 조건으로 연결했다. 미매칭2개는 위치 추정 없이 남긴다. 2025-10 과거 위치 동일성은 미검증이며 현재 마스터를 이용한 참고 분석이다.
- 출처·해시는 data/processed/planning_sources.json에, 원본은 data/raw에 보존하며 Git에는 대용량 원본이나 비밀키를 넣지 않는다.
- OSM 시설 수집은 서비스 응답 제한/타임아웃으로 채택하지 않았으며 최종 분석은 위 공공데이터 시설만 사용한다.

## 전체 커버 영역
도시로 분류된 모든 정류장 좌표의500m 버퍼 합집합을 계산하고 행정 경계로 자른다. 중복 좌표는 동일한 면적을 중복 계산하지 않는다. 지도는 이 전체 영역을2m 허용오차·위상 보존으로 단순화한 GeoJSON을 사용한다. 정류장 표본 점은 위치 참고용이고 음영 생성에는 사용하지 않는다. 정확한 면적은 단순화 전 도형으로 산출한다. 원본/단순화 면적과 오차를 결과에 함께 기록한다.

## 신규 입지
500m 격자를 행정 경계로 자르고 대표점을 만든다. 기존 대여소300m 이내는 제외한다. 주변1km 실제 대여량 또는500m 공개 시설이 있는 격자를 평가하여, 기존 대여소가 없는 지역도 시설 근거로 후보가 될 수 있다.
인구밀도·시설 수·주변 대여량·정류장 커버 밖 면적 비율의 도시 내 midrank 백분위 동등가중을 사용한다. 인구는 구·시 밀도이므로 같은 구의 격자 간 인구 차이를 측정하지 못한다. 주변 이용량은 대여소 간 중첩되는 수요 참고값이며 신규 대여소의 예측 이용량이 아니다. 설치 가능 토지·도로 접근·허가·예산은 별도 확인해야 한다.

## 기존 후보 순위
기존 후보 정의 d>500m AND R>0는 보존한다.
취약도 V=max(0,(d-500)/500)*R은 설명용으로 유지한다.
최종 점수는 V 대신 접근성 결손D, 수요R, 잠재 추가 면적P를 각각 한 번씩 반영한다:
S=(F(D)+F(R)+F(P))/3.
후보5개 미만은 화면에서 점수를 강도·우수성으로 보여주지 않고 ‘후보 수 부족’과 거리·수요를 강조한다. API는 호환성을 위해 참고 점수와 score_confidence를 함께 반환한다.
거리300/500/800m × 균등/접근성 우선/수요 우선 가중치의9조건을 계산한다. 기준500m·균등 대비 TOP10 집합 Jaccard 유사도와 공통 후보 평균 순위 변동을 공개한다. 두 TOP10 집합이 모두 비면 Jaccard는 null이며, 공통 후보가 없으면 평균 순위 변동은 null이다.

## 확충·재배치 분리
확충은 위 격자 입지 후보이며, 재배치는 별도로 시간대 대여-반납 순유출입과 관측량·거치 용량을 보여준다. 실제 시점별 재고와 운영 이동 기록이 없어 부족 상태·실행 이동 수량을 생성하지 않는다. 재배치 목록은 수요 관측 기반 검토 대상이다.

## 선택 시나리오
도시별 신규 상위3곳과 기존 취약 상위3곳까지의 모든 부분집합을 사전 계산한다(최대6후보/64조합). 선택한 후보300m 버퍼를 행정 경계로 자르고 기존 정류장 접근 영역을 제외한 합집합이 추가 면적이다. 중복 면적=개별 추가 면적 합-합집합 면적. 여러 후보의 면적을 단순 합산하지 않는다.
이는 후보 연결을 가정한 잠재 면적 비교이며 실제 환승 증가·재배치 효과가 아니다. 현재 연결 대여소의 기존 시나리오와 신규 후보 선택 시나리오는 구분한다.

## 기간·오류
공통 비교는 서울·대전의 실제 공통 관측 기간만 사용하며 세종2025-10을2026-10에 합산하지 않는다. 세종 단독 화면은2025-10을 선택한다.
미처리 기간409, 범위 밖422, 정류장 부족/좌표 부족/이용 기록 없음/경계 부족은 각각 reason_code로 구분한다. 화면은 해당 원인을 표시한다.

## 재현 가능한 배포
```bash
cd bike-link-analysis
PYTHONPATH=. python scripts/collect/planning_sources.py
PYTHONPATH=. OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python scripts/preprocess/precompute_city_kpis.py --workers 2 --report docs/transit/planning-build.json
# 다른 서버로 코드·입력·집계·manifest를 복사한 후, 재계산 없이 내용 검증
PYTHONPATH=. python scripts/deploy/release.py --verify-only --check-url https://project.wizide.com
```
kpi_inputs.json은 파일별 SHA256과 내용 기반 revision을 보관한다. 파일 수정시각은 버전 자체에 들어가지 않는다. 대상 서버에서 내용 검증 후 로컬 stat receipt를 생성하므로 복사 시각이 달라도 같은 내용은 같은 집계를 사용할 수 있다. 요청 시 거대 DB를 해시하지 않고 검증 영수증과 로컬 변경 여부만 검사한다.
입력이 달라지면 verify-only가 실패하며 배치 재생성이 필요하다. 배치는 코드·자료가 도중에 바뀌면 중단한다. 배포 작업은 단일 입력 스냅샷으로 실행한다.
실제 배포 명령은 release.py의 -- 뒤에 전달한다. 배치·필수 도시·전 액션 검증 성공 후에만 명령을 실행하며, --check-url로 배포 후 준비 상태를 검사한다. /api/health는 생존 확인, /api/readiness 및 WIZ readiness는 집계 준비 확인이다. 별도 외부 CI나 GitHub push는 이 작업에서 수행하지 않는다.
